Add two features to the admin portal:

1. Auto-sync client invoices when time entries are edited via the admin grid
Right now, when an admin creates, edits, or deletes a time entry through the generic admin CRUD grid (POST/PUT/DELETE /admin/tables/time_entries), the weekly client invoice is never updated. Fix this so the invoice always reflects the current approved hours.

Rules:

POST (create): After insert, if the new time entry has approvalStatus = 'approved', call the existing upsertWeeklyInvoiceForTimeEntry function to roll it into the draft invoice for that site/week.
PUT (edit): Fire upsertWeeklyInvoiceForTimeEntry when the entry is currently approved OR was previously approved (downgrading from approved to pending/rejected should remove those hours from the invoice). If the clock-in time, siteId, or shiftId changed and the old entry was approved, also re-sync the old site/week so stale hours are removed.
DELETE: Snapshot the row before deletion. After sending the 204, if the deleted entry was approved, re-sync that site/week invoice to remove the hours.
Use a fire-and-forget (void) pattern — don't await the sync in the response path.
The upsertWeeklyInvoiceForTimeEntry function and weekStartIsoUtc helper should already exist in lib/invoiceSync.ts.
2. Analytics / Metrics Dashboard page in the admin portal
Add a full analytics dashboard at /analytics in the admin portal, accessible from the Accounting nav group.

API endpoint: GET /analytics/summary?start=YYYY-MM-DD&end=YYYY-MM-DD (admin-only)

The endpoint should return one JSON object with:

Revenue — sum of bill_rate × hours for approved time entries in the period
Labor cost — sum of pay_rate × hours for approved time entries
Gross P&L — revenue minus labor cost
Margin % — P&L / revenue × 100
Hours worked — total approved hours clocked
Hours scheduled — total hours from shifts in the period
Coverage % — hours worked / hours scheduled × 100
No-shows — shifts where headcount > 0 and no accepted assignment showed up
Unfilled shifts — shifts where filled < headcount at end of period
Incidents — count broken out by severity (low, medium, high, critical) and by status (open, resolved)
Weekly trend series — array of { weekStart, revenue, laborCost, pnl, hoursWorked, incidentCount } bucketed by ISO week, covering the full date range. Important: use PAYROLL_TIMEZONE (default America/Chicago) when bucketing by calendar week so evening shifts don't bleed into the wrong week.
Per-site breakdown — array of { siteId, siteName, clientName, revenue, laborCost, pnl, hoursWorked, coveragePct } sorted by revenue descending
Admin portal page (Analytics.tsx):

Date preset bar: This Week / Last Week / Month to Date / Last 30 Days / Custom range picker. Default to Last 30 Days on load.
KPI cards row: Revenue, Labor Cost, Gross P&L (with margin %), Hours Worked, Coverage %, Total Incidents — each as a card with the number and a subtle label.
P&L bar chart (Recharts BarChart): weekly bars for Revenue vs Labor Cost, with a line for P&L. Gold/navy brand colors.
Hours area chart (Recharts AreaChart): weekly Hours Worked vs Hours Scheduled.
Incidents line chart (Recharts LineChart): weekly incident count trend.
Per-site breakdown table: sortable columns (click header to toggle asc/desc). Columns: Site, Client, Revenue, Labor Cost, P&L, Hours, Coverage %. Highlight negative P&L rows in red.
Missed shifts expandable row showing unfilled shift count and no-show count.
Export buttons: CSV download (all metrics flattened) and PDF download.
Client filter dropdown: filter the entire report to a single client before exporting or reviewing.
Officer Performance section: per-officer table showing hours worked, shifts completed, incidents filed, punctuality %, and a sparkline trend. Include a date-range filter. Add regression tests for the overnight-shift punctuality calculation (a shift that starts at 11 PM and ends at 7 AM the next day should count as punctual if the officer clocked in before 11 PM, not the next morning).
